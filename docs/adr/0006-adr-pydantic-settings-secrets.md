# ADR 0006: pydantic-settings для секретов

- **Status:** Accepted
- **Date:** 2026-09-10
- **Updated:** 2026-09-16
- **Related:** ADR 0001 (project dump), ADR 0012 (модели), ADR 0018 (Этап 4)

## Context

Токены ботов, ID чатов и другие секреты не должны попадать в публичный репозиторий. Рассматривались хардкод, YAML-конфиги и переменные окружения.

## Decision

Использовать **pydantic-settings** с файлом `.env` для секретов.

- Секреты (токены, ID) — в `.env` (добавлен в `.gitignore`)
- Шаблон `.env.example` — в репозитории (попадает в дамп TOC)
- Публичные настройки (URL, лимиты) — в `config/settings.yaml`

## Consequences

**Положительные:**
- Секреты не попадают в Git
- Единый интерфейс для локальной разработки и продакшена
- Валидация обязательных полей при старте
- `.env.example` виден в дампе TOC (LLM видит шаблон)

**Отрицательные:**
- Требует создания `.env` файла перед первым запуском
- При развёртывании в Docker — передача через `environment` в compose, не через `.env` файл внутри контейнера

**Что теперь нельзя:**
- Нельзя хардкодить секреты в коде
- Нельзя добавлять `.env` в Git
- Нельзя использовать YAML для секретов

**Следующий шаг:**
- S4-05: При развёртывании на `docker_host` — передача секретов через `environment` в compose.
