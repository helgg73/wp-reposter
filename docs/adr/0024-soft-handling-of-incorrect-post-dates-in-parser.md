# ADR 0024: Мягкая обработка некорректных дат постов в парсере

- **Status:** Accepted
- **Date:** 2026-09-16
- **Related:** ADR 0004 (WP REST API), ADR 0016 (Этап 2, S2-07), ADR 0020 (структура модулей)

## Context

WP REST API в редких случаях может вернуть пост с отсутствующим или `null` значением обязательного поля (`date`, `title.rendered`, `guid`, `link`). Это может быть следствием:
- Повреждённой записи в БД WordPress.
- Кастомных плагинов, модифицирующих ответ API.
- Гонки состояний при черновиках.

Ранее парсер использовал прямой доступ к полям (`post["date"]`, `post["title"]["rendered"]`), что приводило к `KeyError` и падению всего цикла обработки источника.

**Требование пользователя:** репостер не должен падать из-за одного некорректного поста. Пост должен быть пропущен с записью в лог.

## Decision

Метод `WordPressParser._format_post()` возвращает `dict | None`:
- `dict` — если все обязательные поля присутствуют и валидны.
- `None` — если хотя бы одно обязательное поле отсутствует, `null` или пустая строка (для `date`).

**Обязательные поля:** `guid`, `title.rendered`, `link`, `date`.

**Обработка в `fetch_posts()`:** если `_format_post()` вернул `None`, пост не добавляется в результат. В лог (пока `print`) пишется предупреждение с идентификатором поста и причиной пропуска.

**Пример:**
```python
if not post.get("date"):
    print(f"⚠️  Пропущен пост {post.get('guid')} без 'date' (null или отсутствует)")
    return None
```

## Alternatives considered

- **A. Жёсткая валидация (`ValueError`).** Отвергнуто: падение всего цикла из-за одного поста неприемлемо для фонового сервиса.
- **B. Fallback-значения (пустая строка, текущая дата).** Отвергнуто: маскирует проблему, может привести к некорректной обработке (например, отправка поста без ссылки).
- **C. Мягкая обработка с пропуском (выбрано).** Пост пропускается, проблема видна в логах, цикл продолжается.

## Consequences

**Положительные:**
- Репостер устойчив к аномальным данным от WP API.
- Проблема видна в логах (можно диагностировать).
- Один некорректный пост не блокирует обработку остальных.

**Отрицательные:**
- Некорректные посты не будут отправлены (это осознанное решение).
- Требуется мониторинг логов на предмет частых пропусков (сигнал о проблемах на стороне WP).

## Связь с задачами

- **S2-07** (ADR 0016): проверка `published` на `null` — часть этого решения.
- Тесты: `TestFormatPostValidation` в `tests/test_parser.py`.

## Done criteria

- `_format_post()` возвращает `None` при отсутствии/`null` обязательных полей.
- `fetch_posts()` пропускает посты, для которых `_format_post()` вернул `None`.
- В лог пишется предупреждение с причиной пропуска.
- Тесты покрывают все случаи: missing guid, missing title, missing link, missing date, null date, empty date.
- Валидный пост корректно возвращается.

## Not to touch

- ADR 0004 не редактируется.
- Логика `_should_exclude()` не меняется.
- В `main.py` проверка `if newest_sent_date:` уже защищает `update_cutoff_date()` от `None` — дублировать не нужно.
