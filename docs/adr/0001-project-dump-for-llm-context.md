# ADR 0001: Дамп репозитория в один файл для LLM

- **Status:** Proposed
- **Date:** 2026-09-15

## Context

При работе с LLM (ChatGPT, Claude, локальные модели) над проектом
возникает задача передать модели контекст: структуру и содержимое
кода. Ручное копирование файлов в чат — медленно, ведёт к пропускам
и не воспроизводится.

Прямые альтернативы:

1. **Готовые инструменты** (Repomix, code2prompt, Gitingest) —
   зрелые, но тянут зависимости (Node.js, Rust), избыточны для
   небольших проектов, и часть из них отправляет код на свои серверы.
2. **Ручной сбор** — не масштабируется, легко забыть файл.
3. **MCP-серверы** — требуют настройки клиента, привязывают к
   конкретному инструменту (Claude Desktop, Cursor).

Контекстное окно LLM также накладывает ограничение: дамп должен
быть предсказуем по объёму, чтобы не улететь в «жёлтую зону»
деградации качества (>50–80k токенов).

Проект современный, все файлы в UTF-8. Поддержка legacy-кодировок
(Windows-1251, UTF-16) — лишняя сложность для инструмента,
рассчитанного на небольшие актуальные репозитории.

Отдельный риск: случайно закоммиченный `.env` или `credentials.json`
попадёт в дамп и уйдёт в облачную LLM. Это не гипотетический сценарий:
коммит `.env` — одна из самых частых ошибок в небольших проектах,
где нет pre-commit-хуков и review-процесса. Утечка необратима:
даже если потом удалить файл из репозитория и перегенерировать дамп,
содержимое остаётся в истории чата с моделью.

## Decision

Написан собственный скрипт `project_dump.py`, который:

- запускается из корня репозитория;
- использует `git ls-files` для получения списка отслеживаемых
  файлов — так `.gitignore`, вложенные `.gitignore` и глобальный
  `~/.gitignore` работают автоматически, без парсинга своими руками;
- пропускает бинарные файлы (эвристика по NUL-байту в первых 8 KB;
  ложные срабатывания на UTF-16 — см. Consequences);
- пропускает lock-файлы и сгенерированный код через `EXCLUDE_PATTERNS`;
- пропускает Markdown-файлы (`*.md`) — документация полезна человеку,
  но в дампе кода для LLM она только занимает токены. При
  необходимости конкретный `.md` можно вернуть в дамп через
  добавление в `ALLOW_PATTERNS`;
- исключает из дампа потенциальные секреты: `.env`, ключи и
  сертификаты (`*.key`, `*.pem`, `*.p12`), `credentials.*`,
  `secrets.*`, SSH-ключи, конфиги облачных сервисов;
- эвристика «похоже на секрет» проверяет имя файла по подстрокам
  (`secret`, `password`, `credential`, `token`, `apikey`, `api_key`,
  `private`). Hint `auth` исключён из списка: он даёт массовые
  ложные срабатывания на документации (`AUTHORS`, `authentication.md`,
  `authorization.md`). Файлы вида `auth.json` с токенами эвристикой
  не ловятся — это осознанный компромисс;
- сравнивает имена файлов с паттернами регистронезависимо и
  кроссплатформенно: `*.KEY`, `*.key`, `Private.Key` отсеиваются
  одинаково на Windows и Linux. Реализовано через `fnmatchcase`
  с ручной нормализацией регистра;
- сохраняет в дампе шаблоны `.env` без реальных секретов
  (`.env.example`, `.env.sample`, `.env.template`, `.env.dist`):
  они полезны, чтобы LLM видел ожидаемые переменные окружения.
  Реализовано через allow-list, который проверяется после
  пользовательских `-x`, но до встроенных `EXCLUDE_PATTERNS`;
- пишет результат в `project_dump.txt` с оглавлением в начале
  и заголовками `===== path =====` перед каждым файлом;
- печатает предварительную оценку объёма в байтах и токенах до
  записи, предупреждает при превышении порога;
- поддерживает флаги:
  - `-o` — имя выходного файла;
  - `-x` / `--exclude` — дополнительный glob-паттерн исключения;
  - `--no-toc` — отключить оглавление;
  - `--max-bytes` — прервать при превышении лимита;
  - `--no-default-excludes` — не применять встроенные исключения
    (для отладки или если фильтрация не нужна);
  - `--force` — продолжить, несмотря на найденные подозрительные файлы;
- использует коды возврата: 0 — успех, 1 — ошибка git, 2 — превышен
  `--max-bytes`, 3 — нечего дампить, 4 — найдены файлы, похожие
  на секреты (нужен `--force`).

Скрипт остаётся одним файлом без внешних зависимостей (только
стандартная библиотека). Это осознанный выбор в пользу простоты
для небольших проектов.

## Consequences

**Положительные:**

- Воспроизводимость: один и тот же дамп получается на любой машине
  с тем же набором закоммиченных файлов.
- Кроссплатформенная воспроизводимость: одинаковые правила
  сравнения имён файлов на Windows и Linux, дампы совпадают
  по составу независимо от ОС.
- Пустой результат (все файлы отфильтрованы) не создаёт файл
  и завершается с кодом 3 — защита от случайной передачи пустого
  дампа в LLM.
- Нулевые зависимости: работает на голом Python 3.9+.
  Более старые версии (включая 3.5) не поддерживаются из-за
  f-strings, `subprocess.run(capture_output=...)` и PEP 585-аннотаций
  (`list[str]`, `dict[str, int]`).
- Прозрачность: скрипт читается за 5 минут, все настройки в шапке.
- Контроль объёма: оценка токенов до записи, `--max-bytes`,
  `-x` / `--exclude`.
- Защита от случайной утечки секретов: подозрительные файлы
  блокируют запись дампа до явного подтверждения через `--force`.
- Шаблоны `.env.example` остаются в дампе, давая LLM контекст
  о переменных окружения проекта.

**Отрицательные:**

- Не масштабируется на очень большие проекты: полный дамп может
  не влезть в контекст, придётся дампить поддеревья вручную.
- Оценка токенов грубая (`bytes / 4`), погрешность ±20%.
- `git ls-files --cached` не видит неотслеживаемые файлы, что
  обычно правильно, но требует `git add` для новых файлов.
- Нет автоматической интеграции с LLM-клиентами (в отличие от
  MCP-серверов), каждый раз нужно копировать результат в чат.
- Не поддерживаются файлы в кодировках, отличных от UTF-8:
  Windows-1251 и подобные не отсеиваются эвристикой бинарности
  (NUL-байта в них нет) и попадают в дамп с заглушками `�`.
  Скрипт предупреждает об этом в stderr с указанием файла и
  позиции ошибки, но не блокирует запись.
- Эвристика бинарности (поиск NUL-байта) ложно срабатывает на
  UTF-16: такие файлы будут пропущены как бинарные. Для
  UTF-8-проектов это не проблема, для смешанных — потребуется
  доработка.
- Защита от секретов работает только по имени файла. Файлы с
  нейтральным именем (`config.yaml`) или с `auth` в имени
  (`auth.json`), содержащие ключи или пароли, в дамп попадут.
  Проверка содержимого на паттерны (`AKIA...`,
  `-----BEGIN PRIVATE KEY-----` и т.п.) в текущем решении
  не реализована.
- Эвристика «похоже на секрет» может давать ложные срабатывания
  на файлах с `token`, `password`, `credential`, `private` в имени
  (например, `tokenizer.md`, `password_policy.yaml`). Лечится
  флагом `--force` или добавлением в `-x`.
- Allow-list шаблонов `.env` может устареть: если в проекте
  появится новый формат шаблона (например, `.env.local.example`),
  его нужно добавить в `ALLOW_PATTERNS`. Пользователь может
  явно исключить шаблон через `-x`, если он не нужен.

**Что теперь нельзя / не нужно:**

- Не нужно парсить `.gitignore` самостоятельно — git делает это
  лучше.
- Вывод `project_dump.txt` прописан в `.gitignore`, поэтому git
  его не отслеживает. Это даёт две вещи: файл не попадёт в коммит
  случайно, и `git ls-files` его не вернёт, то есть в сам дамп он
  тоже не попадёт — без дополнительных исключений в скрипте.
