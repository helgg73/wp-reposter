# ADR 0002: Менеджер пакетов — uv

- **Status:** Accepted
- **Date:** 2026-09-15
- **Related:** ADR 0003 (ruff), ADR 0012 (единый источник моделей)

## Context

Нужен современный менеджер пакетов для Python-проекта: lock-файлы, группы зависимостей (dev/prod), быстрая установка, нативная поддержка Windows, лёгкая интеграция с Docker.

Прямые альтернативы:

1. **pip + requirements.txt** — стандарт де-факто, но нет lock-файлов, нет групп зависимостей, медленная установка.
2. **Poetry** — зрелый, но медленнее, свой DSL для конфигов (`[tool.poetry]`), тяжелее для Docker-образов.
3. **PDM** — менее зрелый, меньше комьюнити.

## Decision

Использовать **uv** от Astral.

Реализация:

- **Файл:** `pyproject.toml`
- **Секции:** `[project].dependencies`, `[dependency-groups].dev`
- **Ключевые поля:**
  - `requires-python = ">=3.12"`
  - Зависимости: `httpx>=0.27.0`, `pydantic>=2.7.0`, `pydantic-settings>=2.2.0`, `pyyaml>=6.0.1`, `maxapi>=1.2.0`
  - Dev-группа: `pytest>=8.2.0`, `pytest-asyncio>=0.23.6`, `respx>=0.21.0`, `ruff>=0.4.0`
- **Lock-файл:** `uv.lock` — в репозитории есть. **Осознанно не включается в дамп TOC** (см. ADR 0001: `EXCLUDE_PATTERNS` пропускает lock-файлы, чтобы не раздувать дамп).

## Consequences

**Положительные:**

- Скорость установки в 10–100 раз выше pip/poetry (написан на Rust).
- Детерминированные сборки через `uv.lock`.
- Группы зависимостей без дополнительного DSL.
- Полная совместимость с pip-экосистемой.
- Нативная поддержка Windows.
- Лёгкие Docker-образы на Этапе 4.

**Отрицательные:**

- Экосистема менее зрелая, чем у poetry (но быстро развивается).
- `uv.lock` не виден в дампе TOC — LLM не сможет увидеть точные зафиксированные версии. При необходимости можно передать `uv.lock` в чат отдельно.

**Что теперь нельзя / не нужно:**

- Не нужно вести `requirements.txt` параллельно — источник истины один, `pyproject.toml`.
- Не нужно парсить `pyproject.toml` вручную для установки — uv делает это сам.
- Не нужно добавлять `uv.lock` в дамп TOC — это осознанное решение (см. ADR 0001).
