# ADR 0005: Асинхронная архитектура на asyncio

- **Status:** Accepted
- **Date:** 2026-09-10
- **Updated:** 2026-09-16
- **Related:** ADR 0004 (WP REST API), ADR 0008 (maxapi), ADR 0013 (синхронный парсер), ADR 0016 (Этап 2)

## Context

Проект должен работать как фоновый сервис с интервалом проверки 5 минут. Рассматривались синхронный цикл с `time.sleep()` и асинхронный подход.

## Decision

Использовать **asyncio** для всей архитектуры.

- `main.py` — асинхронный цикл
- `exporter.py` — async методы
- `state.py` — sync (файловые операции быстрые)
- `parser.py` — **синхронный на Этапе 1** (см. ADR 0013)

## Consequences

**Положительные:**
- Готовность к переходу на FastAPI (Этап 4)
- Корректное завершение по сигналу
- Параллельная обработка нескольких источников (в будущем)

**Отрицательные:**
- Требует понимания async/await от разработчика
- Парсер блокирует event loop на Этапе 1

**Что теперь нельзя:**
- Нельзя использовать `time.sleep()` — только `await asyncio.sleep()`
- Нельзя блокировать event loop долгими операциями

**Следующий шаг:**
- На Этапе 2 (S2-11) парсер будет переведён в async (см. ADR 0016).
- На Этапе 4 — переход на FastAPI (APScheduler в lifespan).
